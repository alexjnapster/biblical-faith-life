# Declared local runtime

The manifest launches `scripts/bfl_mcp.py` over stdio using Python 3.9 or later. This is a local server, not a hosted remote connector. It opens no listening port and starts no scheduler or background publishing loop. It executes the existing engine functions in-process, without a shell, dynamic code evaluation, or package installation.

Configure an existing dedicated workspace in the plugin options before using storage, checkpoints, visual exports or draft submission. Tool paths are relative to that workspace; traversal, symlinks, hard-linked files and paths into the installed plugin are rejected. Existing libraries are bound to the configured owner label. Read tools open existing library databases in read-only mode. Choose the original owner label to reopen an older library. Do not use another person's workspace.

The 12 tools are bfl_status, bfl_validate, bfl_library_ingest, bfl_library_search, bfl_library_get, bfl_workflow_start, bfl_workflow_record, bfl_workflow_status, bfl_visual_export, bfl_draft_preview, bfl_draft_submit and bfl_draft_verify. Each tool exposes its exact input schema and read-only/destructive/open-world annotations. Text files and structured content are supplied through tool arguments; the server does not search the user's documents or histories. Normal file generation in a host remains subject to that host's actual capabilities and user permissions.

The Church UA origin and optional existing key are selected by the user in plugin configuration. The key option is sensitive and is passed only to the declared server env, never substituted into skill text. The server does not fall back to ambient application credentials. No key is needed for core local features or draft preview. Each submission requires explicit authorization and an exact reviewed payload hash. The attempt journal prevents automatic duplicate submissions after process or transport failure. A receipt read-back verifies ID and selected draft-state fields, not the full article body. A valid read scope is required for read-back; a created draft with pending read-back must not be submitted again.

Visual export creates a new directory and does not overwrite existing files. SVG and HTML work with the standard library. Native PDF and PowerPoint need the pinned optional dependencies documented in skills/biblical-faith-life/scripts/native-export-requirements.txt and suitable fonts. A partial export is reported explicitly rather than claiming every requested format exists.

This is a local OS-user boundary, not a remote multi-tenant service. Actor labels and structural gates do not certify independent review or substantive quality. Review actual artifacts before use. This package has no autonomous public publishing tool.
